# 럭키 스크래치 기획서

모든 수치의 원본은 `js/economy.js`다. 이 문서의 표는 그 파일에서 뽑았다. 수치를 바꾸면 `npm run ev`와 `npm run sim`으로 [EV.md](EV.md)와 [SIMULATION.md](SIMULATION.md)를 다시 만든다.

## 1. 한 줄 요약

편의점 알바생이 광클로 번 돈을 동네 복권방에서 즉석 복권으로 긁어 인생역전을 노리는 모바일 세로형 웹게임이다.
핵심 감정은 긁는 순간의 긴장감과 당첨 연출이다.

## 2. 설계 원칙

1. **처음엔 본업, 갈수록 복권.** 첫 복권까지 탭 약 80회가 필요하다. 탭 수입은 레벨마다 ×1.3, 비용은 ×1.45씩 늘어서 후반에는 복권이 주 수입원이 된다.
2. **복권의 기본 기대값은 최대 120%.** 운이 좋으면 이익이 조금 남는 수준이다. 행운 부적 레벨업으로 계속 오른다.
3. **잭팟 없음.** 최고 배수는 20~50배로 묶었다. 1000배처럼 한 번에 진행을 건너뛰는 당첨은 없다.
4. **분산을 통제한다.** 행운 부적은 당첨금 배수가 아니라 당첨 확률(꽝 → 소액 당첨)을 올린다. 분산을 거의 늘리지 않고 기대값만 올려서, 보통 플레이어가 파산 루프에 갇히지 않게 했다(9장).
5. **자동화는 긁기만.** 구매는 항상 플레이어가 직접 한다. 접속해 있지 않으면 아무 수익도 없다.
6. **정직한 확률.** 결과는 구매 순간 확정되고, 모든 확률표를 게임 안에서 공개한다. 연속 꽝 보정은 없다. 예외는 첫 플레이 10~30분 사이의 보장 당첨 1회뿐이다(요청 사항).

## 3. 화면 구성(세로 360×640 기준 이상)

| 영역 | 내용 |
|---|---|
| 상단 바 | 보유 금액(크게), 직급, 설정 버튼 |
| 복권대 | 지금 긁는 복권 카드. 쌓인 복권 수와 도우미 진행 표시. 결과가 나오면 같은 자리에 "한 장 더" 버튼 |
| 복권 선택 줄 | 가로로 넘기는 복권 칩. 잠긴 복권은 자물쇠와 해금 비용 표시 |
| 알바 버튼 | 화면 아래 큰 버튼. 탭 수입, 콤보 게이지 |
| 하단 탭 | 복권방 / 강화 / 환생 / 기록 |

- 강화, 환생, 기록 탭은 처음엔 잠겨 있다. 첫 복권을 긁으면 강화와 기록이, 럭키 세븐을 해금하면 환생이 열린다.
- 설정(상단 톱니)에는 효과음, 배경음악(기본 끔), 진동, 효과 줄이기, 지금 저장, 앱 설치, 확률·게임 안내, 로그아웃이 있다.

## 4. 본업(편의점 알바)

- 탭 1회 = 물건 1개 스캔. 기본 10원.
- **광클 콤보.** 1.2초 안에 다시 탭하면 콤보가 이어진다.

| 콤보 | 배율 | 표시 |
|---|---|---|
| 0~19 | ×1 | - |
| 20~49 | ×1.2 | 좋아요 |
| 50~99 | ×1.5 | 손이 빨라요! |
| 100+ | ×2 | 피버 타임! |

- **승진(레벨업).** 탭 수입 ×1.3/레벨, 비용 ×1.45/레벨. 3레벨마다 호칭이 바뀐다(신입 알바 → … → 회장).

| 레벨 | 호칭 | 탭당 기본 수입 | 다음 레벨 비용 |
|---|---|---|---|
| 0 | 신입 알바 | 10원 | 150원 |
| 6 | 야간 알바 | 48원 | 1,400원 |
| 12 | 부매니저 | 233원 | 13,000원 |
| 18 | 부점장 | 1,125원 | 120,000원 |
| 24 | 지점장 | 5,428원 | 1,100,000원 |
| 30 | 상무 | 26,200원 | 10,000,000원 |
| 36 | 부사장 | 126,462원 | 97,000,000원 |
| 42 | 회장 | 610,409원 | 900,000,000원 |

본업 자동화는 없다.

## 5. 복권

### 5.1 종류와 규칙

기본 6종은 1회차부터 돈으로 해금한다. 추가 5종은 환생할 때마다 하나씩 열린다.

| # | 이름 | 가격 | 해금 비용 | 규칙 |
|---|---|---|---|---|
| 1 | 동전 줍기 | 1,000원 | - | 6칸 중 같은 금액 3개 → 그 금액 |
| 2 | 네잎클로버 | 6,000원 | 15,000원 | 행운 번호 2개 vs 내 번호 6개, 같으면 그 칸 금액 |
| 3 | 럭키 세븐 | 4만 원 | 12만 원 | 3줄 슬롯, 한 줄에 같은 그림 3개 → 그림 상금 |
| 4 | 열쇠와 금고 | 25만 원 | 90만 원 | 9칸 중 열쇠 3개 → 금고 속 금액 |
| 5 | 숫자 대결 | 150만 원 | 600만 원 | 상대 숫자보다 큰 내 숫자 → 옆 금액 |
| 6 | 보석 배수 | 1,000만 원 | 4,500만 원 | 보석 칸 금액 × 배수 칸 |
| 7 | 황금 동전 | 6,000만 원 | 3억 원 | 9칸 같은 금액 3개 (환생 1회) |
| 8 | 별빛 번호 | 4억 원 | 22억 원 | 별빛 번호 3개 vs 내 번호 8개 (환생 2회) |
| 9 | 왕관 슬롯 | 25억 원 | 150억 원 | 4줄 슬롯 (환생 3회) |
| 10 | 해적 금고 | 150억 원 | 1,000억 원 | 12칸 열쇠 3개 (환생 4회) |
| 11 | 다이아 대결 | 1,000억 원 | 7,000억 원 | 숫자 대결 6줄 (환생 5회, 무한 모드) |

- 가격은 단계마다 약 6.25배, 해금 비용은 가격의 2.5~7배다.
- 결과는 **구매 순간 확정**된다. 긁기는 공개 연출이다. 새로고침해도 결과가 바뀌지 않도록 쌓인 복권의 결과까지 저장한다.
- **황금 복권.** 2% 확률로 금박 복권이 나온다. 긁기 전부터 금색으로 빛나고 당첨금이 2배다(기대값 +2%). 클로버 강화로 확률이 오른다.

### 5.2 확률과 기대값

등급 확률은 `p ∝ 배수^(-α)` 꼴로 정했다. α는 복권마다 목표 당첨률과 목표 기대값을 동시에 맞추도록 풀었다(`tools/solve-tables.mjs`).

| 복권 | 당첨률 | 기본 기대값 | 분산 σ² | 최고 배수 |
|---|---|---|---|---|
| 동전 줍기 | 48% | 105% | 4.1 | 20배 |
| 네잎클로버 | 47% | 108% | 4.5 | 20배 |
| 럭키 세븐 | 46% | 111% | 5.6 | 25배 |
| 열쇠와 금고 | 45% | 114% | 8.6 | 30배 |
| 숫자 대결 | 45% | 117% | 9.1 | 30배 |
| 보석 배수 | 44% | 120% | 10.7 | 50배 |
| 7~11번 | 44~45% | 120% | 12~15 | 50배 |

등급별 상세 확률은 [EV.md](EV.md)에 있다. 예를 들어 동전 줍기는 꽝 52%, 본전 26.6%, 2배 10.5%, 3배 6.1%, 5배 3.1%, 10배 1.2%, 20배 0.48%(약 209장에 1번)이다.

### 5.3 연출 강도 구분

| 배수 | 이름 | 연출 |
|---|---|---|
| 0 | 꽝 | 회색 도장, 낮은 효과음. 니어미스면 "아깝다!" |
| 1 | 본전 | 작은 칩, 딩 |
| 2~4 | 당첨 | 금액 떠오름, 2음 효과음, 당첨 칸 빛남 |
| 5~19 | 중박 | 동전 분수, 약한 흔들림, 아르페지오, 짧은 진동 |
| 20~49 | 대박 | 화면 어둡게 + 섬광 + 금액 카운트업 + 꽃가루 + 팡파르 + 진동 패턴 |
| 50 | 초대박 | 대박 연출을 길게(약 3.5초) + 금빛 광선 + "초대박!" |

### 5.4 긴장감

- 칸을 50% 이상 긁으면 그 칸이 "공개"되어 톡 소리가 난다.
- **3개 중 2개가 보이고 나머지 칸이 남은 순간**(같은 금액 2개, 열쇠 2개, 슬롯 앞 2칸 일치 등)에 해당 칸이 빛난다. 동시에 심장 박동 소리와 짧은 진동이 나온다.
- 전체 은박의 일정 비율(도구에 따라 70%→42%) 이상 긁으면 나머지가 벗겨지며 결과가 확정된다.

### 5.5 니어미스

꽝 판은 먼저 자연스럽게 무작위로 만든다. 그 위에 **10% 확률로 "아깝다" 판을 추가로** 만든다(요청: 자연 발생 + 10%).

| 규칙 | 니어미스 모양 |
|---|---|
| 같은 금액 3개 | 최고 금액이 2개 |
| 번호 맞추기 | 최고 상금 칸 번호가 행운 번호와 1 차이 |
| 슬롯 | 한 줄 앞 2칸이 최고 그림 |
| 열쇠 | 열쇠 2개, 금고에는 큰 금액 |
| 숫자 대결 | 최고 상금 줄이 상대와 동점(동점은 꽝) |
| 보석 배수 | 보석 없음 + 배수 ×10 |

### 5.6 첫 플레이 보장 당첨

- 계정 생성 시 10~30분 사이의 무작위 시각을 정한다.
- 누적 플레이 시간이 그 시각을 넘긴 뒤 처음 사는 복권은 "25배 이하 중 최고 등급"으로 확정된다(동전 줍기 20배, 럭키 세븐 25배 등).
- 그전에 자연적으로 20배 이상을 맞혔다면 보장은 생략한다. 1회차 1번뿐이고, 이후로는 확률대로다.

## 6. 성장 요소

### 6.1 강화(회차마다 초기화)

| 강화 | 효과 | 비용 |
|---|---|---|
| 승진 | 탭 수입 ×1.3/레벨 | 150원 × 1.45^레벨 |
| 긁개 | 6단계 도구 진화(10원 동전 → 500원 동전 → 포인트 카드 → 전용 긁개 → 황금 긁개 → 전동 긁개), 단계당 3레벨. 반경 15→70px, 자동 완료 70%→42% | 1,500원 × 2.7^레벨 |
| 행운 부적 | 1~15레벨: 레벨당 꽝 2%p → 낮은 3개 등급 당첨으로 이동. 16레벨부터 레벨당 당첨금 +3% (무제한) | 3,000원 × 2.1^레벨 |
| 도우미 고용 | 자동 긁기 도우미 1/2/3명 | 2만 / 300만 / 3억 원 |
| 도우미 교육 | 한 장 18초 → 5초(8레벨) | 25,000원 × 2.4^레벨 |
| 묶음 구매 | ×5 / ×10 / ×20 | 15,000원 / 30만 원 / 3,000만 원 |
| 판돈 올리기 | 무한 모드 전용. 단계마다 모든 복권 가격·당첨금 ×10 | 5조 원 × 40^단계 |

- 도우미는 쌓인 복권만 긁는다. 보상은 직접 긁을 때와 같다. 속도는 직접 긁기(약 2~5초)보다 훨씬 느리다(5~18초).
- 플레이어가 알바를 탭하는 동안에도 도우미가 쌓인 복권을 긁는다. 구매를 자동으로 하지는 않는다.

### 6.2 환생

- 환생 조건: 이번 회차의 **최고 보유액**이 목표에 도달.

| 회차 | 목표 | 환생 보상 해금 |
|---|---|---|
| 1 | 30억 원 | 황금 동전 |
| 2 | 300억 원 | 별빛 번호 |
| 3 | 3,000억 원 | 왕관 슬롯 |
| 4 | 2.5조 원 | 해적 금고 |
| 5 | 15조 원 | 다이아 대결 + 무한 모드 |

- 클로버 = ⌊10 × (1 + 0.5 × 환생 횟수) × √(최고 보유액 / 목표)⌋. 목표를 넘길수록 조금씩 더 받는다.
- 5번째 환생이 마지막이다. 그 뒤는 **무한 모드**로, 환생 없이 판돈 올리기와 행운 부적으로 끝없이 성장한다.
- 환생하면 돈, 강화, 해금이 초기화된다. 클로버 강화, 기록, 업적, 플레이 시간은 유지된다.

| 클로버 강화 | 효과 | 최대 | 비용(클로버) |
|---|---|---|---|
| 알바의 달인 | 탭 수입 +50% | 20 | 2 + 2×레벨 |
| 네잎 부적 | 당첨금 +5% | 20 | 3 + 3×레벨 |
| 비상금 | 시작 자금 2만 / 30만 / 500만 / 8,000만 / 10억 | 5 | 4 + 4×레벨 |
| 도우미 교육 | 도우미 시간 ×0.9 | 10 | 3 + 3×레벨 |
| 황금 손 | 황금 복권 확률 +1%p | 5 | 5 + 5×레벨 |
| 단골 할인 | 해금 비용 -5% | 8 | 4 + 4×레벨 |
| 손에 익은 도구 | 환생 후 긁개 1단계 유지 | 3 | 6 + 6×레벨 |

## 7. 진행 속도 검증(시뮬레이션)

`tools/simulate.mjs`가 사람 플레이를 흉내 내는 봇으로 1회차부터 무한 모드까지 돌린다. 전체 결과는 [SIMULATION.md](SIMULATION.md)에 있다.

**플레이어 모델 가정(기본형)**
- 초당 5탭.
- 직접 긁기 시간 = 1.2초(구매·확인) + 은박 면적 × 완료 비율 ÷ (도구 지름 × 700px/초 × 효율 0.55) + 0.4초.
- 당첨 연출 시간은 별도로 더한다.
- 최신 복권 가격이 보유액의 절반 이하면 그 복권을 묶음으로 산다. 아니면 알바를 탭한다.
- 다음 해금 비용의 30%가 모이면 복권을 멈추고 저축한다. 강화는 보유액의 50% 이하일 때 싼 것부터 산다.

**결과(기본형, 시드 100개 중앙값)**

| 회차 | 소요 시간 |
|---|---|
| 1회차 | 59분 |
| 2회차 | 62분 |
| 3회차 | 65분 |
| 4회차 | 75분 |
| 5회차 | 86분 |
| 마지막 환생까지 누적 | 약 5.8시간 |

- 첫 복권까지 탭 약 81회(요청 70~100).
- 1회차 해금 시점: 네잎클로버 3분, 럭키 세븐 6분, 열쇠와 금고 12분, 숫자 대결 18분, 보석 배수 27분. 보장 당첨은 약 18분.
- 1회차 중 20배 이상 당첨은 중앙값 13회(약 4~5분마다 한 번).
- **신중형**(초당 3.5탭, 보유액 25% 이하로만 구매)은 회차당 약 2시간이 걸린다.
- **공격형**(초당 7탭, 가진 돈을 모두 거는 플레이)은 회차당 약 45~70분이 걸리고, 파산을 자주 겪는다.

모든 모델에서 회차당 1~2시간 범위에 대체로 들어온다.

## 8. 오래 머무르게 하는 장치(목표: 한 번에 30분 이상)

- **짧은 목표의 연속.** 화면에 "다음 목표"(다음 해금이나 강화까지 남은 금액) 진행 막대를 항상 보여준다. 1회차 기준 새 복권은 3~10분마다, 강화는 1~2분마다 하나씩 살 수 있다.
- **가변 보상.** 당첨률 44~78%로 자주 맞고, 중박은 수십 장에 한 번, 대박은 4~5분에 한 번 정도 나온다.
- **기대 순간.** 황금 복권 등장, 2개 일치 순간의 심장 박동, 니어미스 같은 장면을 넣었다.
- **광클 피버.** 알바를 20초 이상 연타하면 수입이 2배가 된다.
- **도우미 병행.** 알바를 탭하는 동안 도우미가 쌓인 복권을 긁어서, 탭하는 시간에도 당첨 소식이 들어온다.
- **진척 연출.** 승진 호칭, 도구 진화, 새 복권 공개, 업적 달성마다 짧은 축하 연출이 나온다.
- 일일 보상과 오프라인 보상은 넣지 않았다(요청).

## 9. 왜 이 수치인가(밸런스 근거)

1. **파산 루프 문제.** 초기안(최고 1000배 제거 후 50배, 행운 = 당첨금 배수)으로 돌리면 봇이 6시간이 지나도 3번째 복권에 머물렀다. 분산 σ²가 9~17이면 켈리 기준 안전 베팅 비율이 보유액의 1~3%뿐이다. 보통 사람처럼 10% 이상 걸면 돈이 늘지 않는다.
   → 대응: 꼬리 배수를 낮추고(σ² 4~15), 행운 부적을 "당첨 확률 증가"로 바꿨다. 행운 15레벨이면 럭키 세븐의 켈리 비율이 약 9%로 올라간다.
2. **시간 효율 문제.** 탭 수입이 너무 빠르게 크면 싼 복권을 긁는 시간이 손해가 된다(탭 2,000원/초 vs 복권 30원/초). 탭 성장률(×1.3)보다 비용 성장률(×1.45)을 높게 잡아 균형을 맞췄다. 그 결과 "최신 복권 1장 ≈ 탭 수십~수백 회"가 유지된다.
3. **환생 목표**는 각 회차가 1~2시간이 되도록 시뮬레이션으로 맞췄다.

## 10. 저장·로그인

- 아이디: 한글 완성형 2~13자. 비밀번호: 숫자 4자리. Google 시트에 원문 텍스트로 저장한다(앞자리 0 보존).
- 로그인해야 플레이할 수 있다. 같은 브라우저에서는 자동 로그인된다(설정에서 로그아웃).
- 1분마다 서버에 자동저장하고, 성공할 때마다 화면 하단에 "자동저장 완료"를 띄운다. 설정에서 수동저장도 할 수 있다.
- 브라우저에는 5초마다 저장한다. 오프라인이면 "오프라인 상태라 저장하지 않고 있어요. 온라인이 되면 바로 저장돼요"를 1분마다 띄운다. 연결되는 즉시 저장한다.
- **같은 계정은 나중에 로그인한 기기만 유지**한다. 앞 기기는 다음 저장 때 "다른 기기에서 접속됨" 창을 띄우고 멈춘다.
- 플레이 시간(화면이 보이는 동안만 계산)은 시트에만 기록하고 게임 화면에는 표시하지 않는다(요청 41-A).

## 11. 기술

- 빌드 도구 없는 순수 HTML/CSS/JS(ES 모듈)로 만들고, GitHub Pages(Actions)로 배포한다.
- 서버는 Google Apps Script 웹앱 + Google 시트다(`apps-script/Code.gs`).
- 테스트:
  - 단위 테스트는 `node --test`로 돌린다.
  - 모의 서버(`tools/mock-server.mjs`)는 Code.gs를 그대로 불러와 실행한다.
  - 모바일 화면 E2E는 Playwright로 확인한다(`tools/e2e.mjs`).
- PWA:
  - 설치 버튼이 있는 브라우저(안드로이드 Chrome 등)에서는 바로 설치된다.
  - iOS는 웹에서 설치를 실행하는 기능이 없어서, 공유 → 홈 화면에 추가 안내 창을 보여준다.
